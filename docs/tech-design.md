# Agent 基建平台技术方案

这份文档说明本地原型怎么实现一期闭环，以及在 redcowork 里按同一条路径重建。它不替代 `docs/PRD.md`。数字和规则以 PRD 为准。

## 1. 实现范围

静态页面，浏览器直接打开，不安装依赖，不请求模型。评审人要亲手完成一次新建到灰度，并在 A、B 上看到门禁和全量回滚。

建设前提写在 PRD 里：已有模型服务、API 网关和离线任务系统。这是方案假设。原型只把批次标识、单条失败和重试入口做成可点击说明，不实现队列。

## 2. 信息架构

- 工作台：A、B、C 和新草稿的状态。
- Agent 详情：规格编辑、离线试跑、影子验证、评测、失败样例、灰度、回滚。
- 调用日志：一次请求的版本、输入、工具、输出、耗时。
- 从模板新建：三个模板只预填配置。

左侧导航：工作台、调用日志、从模板新建。底部评审路径打勾。右上角「恢复演示数据」回到初始样例。

## 3. 规格怎么拆

模板名称保留「在线互动、批量判定、多轮知识问答」。保存下来的配置是：

- 调用方式：在线或批量。C 的模板预填在线，不是第三种运行模式。
- 保留会话：是或否。C 预填为是，并带上下文条数上限。
- 工具：名称、接口、凭证、权限、超时、版本。
- 知识：名称、版本、引用。草稿可以做一次检索测试，结果不进入正式流量。
- 服务接入：`POST /v1/agents/{id}:invoke`。在线且保留会话时带 `session_id`。批量时带 `batch_id`。

草稿可以改提示词、调用方式和会话。灰度或全量后整份规格冻结，版本号不原地变化。之后要点「创建新版本」才能再改，并重新评测。评测绑定整份规格，不只检查提示词。

## 4. 发布规则

这些规则在 `prototype/app.js` 的 `saveGray`、`rollback`、`runEval` 里执行。

- 正式流量指灰度比例大于 0，包括 10% 和 100%。
- `gate.pass` 为假，或通过后又改了提示词、调用方式、会话：可以离线试跑，可以影子验证，不能保存任何正式流量。B 的 v3.3、C 的知识 v3、未评测草稿都走这条。
- A 的格式检查可以通过，但候选 P95 为 210ms，预算为 200ms。超预算时同样不能保存正式流量。回滚不受这个限制。
- 全量时如果当前线上版本不是候选版本，把当前线上版本写入 `previousStable`。全量之后回滚按钮仍指向它。
- 回滚把线上版本设回 `previousStable`，候选版本保留，正式流量比例改为 0。
- 没有 `previousStable` 的第一次发布，保存 0% 不会变成已回滚。停止服务走「下线」：新请求不再进入该 Agent，其余流量继续原有业务流程，没有原流程则转人工。没有旧版本的灰度同样要写明其余流量的去向。

A 的初始状态就是全量 v1.9，`previousStable` 为 v1.8，用来检查全量后回滚还在。

## 5. 对象

- Agent：调用方式、会话、稳定版、上一稳定版、候选版、流量比例、提示词、工具、知识、门禁、延迟预算。
- EvalRun：通过与否、门槛、失败样例。失败样例含输入、输出、原因。
- Release：流量比例。未过门禁或超预算时拒绝写入大于 0 的比例。
- Trace：请求号、版本、输入、工具、输出、耗时。
- Batch：只在 B 上展示。批次 `batch_20261012_03`，失败 14 条，重试按钮只提示已交给既有离线调度。

## 6. 演示数据

与 PRD 第 4 节、第 6 节一致。

- A：在线，不保留会话。全量 v1.9，回滚目标 v1.8。采纳率 31% 对 36%，点击率 4.2% 对 4.8%，次日留存 22.0% 对 23.1%，P95 180ms 对 210ms，预算 200ms。用户哈希分组，样本 12.4 万，观察窗口 48 小时。应回滚。
- B：批量，不保留会话。线上 v3.2。候选 v3.3。准确率 96.1%（门槛 98%），红线召回 91%（门槛 99%），误判率 2.4%，漏判率 8.9%，隐晦导流召回 86%。不能进正式流量。政策若已废止，不恢复旧政策，降级人工。
- C：在线，保留会话。线上 v2，候选知识 v3。总体命中 93%（门槛 95%），关键政策错误 2 条（门槛 0）。一次解决率 71%，转人工率 18%，这两项是观察值。不能灰度。
- 日志：`req_8f21` 是 B 的 v3.2；`req_1c07` 是 A 的 v1.9；`req_77aa` 是 C 的 v2。
- 新草稿：第一次评测给出模拟失败样例。按失败原因补充引用要求后重测通过，才能保存 10%。界面写明这是模拟结果。写「不要引用」不会被当成通过。保存后规格冻结；调成 0% 会提示去点下线。

## 7. 代码包

`prototype/index.html`、`styles.css`、`app.js`。双击 `index.html` 即可。刷新会丢失新建的草稿，用「恢复演示数据」回到 A、B、C。

## 8. redcowork 重建说明

整段贴进 redcowork。做成平台控制台，不要做成穿搭 App、审核后台或客服聊天窗。

