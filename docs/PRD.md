# Agent 基建平台产品思路稿

## 1. 背景与目标

穿搭灵感、生态守护、售后答疑要同时上线。A 面向 C 端，日调用百万级，玩法几乎每周一变。B 按政策批量判定笔记和评论，误判和漏判都会影响处置。C 嵌在客服工作台，在线多轮回答退换货和物流，大促有波峰。三支团队各自从零搭建运行、发布和观测，工程会做三遍，门禁和回退也无法统一。

平台要让业务方从模板创建 Agent，改规格、离线试跑、发起评测、看失败样例、修改后重测，通过之后才能灰度或全量。已发布规格冻结，再改就要新版本并重测。已有上一稳定版时，全量之后仍能回滚；第一次发布没有旧版本，停止服务用下线，不叫回滚。A、B、C 用来检查同一套规则能否挡住不同的错误上线。

三个业务 Agent 的指标说明它们好不好，不说明平台有没有减少重复投入。试点后再定目标，先记三条基线：从创建到首次上线的耗时；发布由业务团队自己完成的比例；共性工具、知识或评测集被第二个团队复用的次数，或因此少掉的重复开发工时。

## 2. 场景差异

调用方式只有在线和批量两种。A 和 C 都是在线调用。B 是批量调用。多轮不是第三种运行模式，而是会话开关。C 在线调用，并且保留会话；A 默认不保留。

迭代原因不同。A 每周改玩法和推荐。B 由政策更新驱动，次数少，但每次都要验证。C 主要更新知识，对话策略相对稳定。

失败代价不同。A 失败时，用户不采纳，点击和留存下降，应马上收流量。B 失败时会误判或漏判，必须追溯到版本和理由。C 失败时会把错误政策告诉用户。

决策指标不同。A 看采纳率、点击、留存，并看有没有越过写明的延迟预算。对比至少要有稳定分组、曝光归因、样本量和观察窗口。B 不能只看总体准确率，红线类别要看召回、误判、漏判和关键切片。C 在总体政策命中之外，退换货、价格、时效这几类关键政策错误单独设门槛。一次解决率和转人工率是上线后的观察值，不能代替门禁。

回滚也有边界。模型、提示词、工具版本可以切回上一稳定版。已经失效的政策不能靠回滚恢复；覆盖不到的请求降级人工。

## 3. 通用骨架

骨架按「构建、运行、发布、观测」来搭。团队差异写进可组合配置。

**身份与配额。** 空间、角色和额度决定谁能创建、谁能发布、流量记在哪个团队。A 的在线实验单独限流。B 的批量任务用独立配额，避免堵住在线请求。C 在大促只调额度，不改规格。

**构建规格。** 一份规格包含这些可组合项，而不是在「在线、批量、多轮」里三选一。

- 调用方式：在线或批量。
- 会话：是否保留会话、会话标识、历史消息、上下文条数上限。
- 模型、提示词、输出结构。
- 工具接入：接口、凭证、调用权限、超时、工具版本。穿搭策略、政策条文、订单接口留在工具后面，平台管接入和版本。
- 知识接入：导入、更新、检索测试、引用片段、知识版本。C 的迭代主要改这里。
- 服务接入：发布后，业务系统走统一调用接口。请求带版本或流量策略，不把 Agent 嵌进各自工程。批量请求还要带批次标识。

**运行时。** 建设前提是方案假设，题目没有给出：公司已有模型服务、API 网关和离线任务系统。一期不重做网关，也不自建调度队列。平台仍要补上没有它们就无法安全上线的部分。在线请求要有超时和降级。批量要有批次标识、单条失败状态和重试入口；调度可以沿用既有离线系统，但这三项必须由平台看见，否则 B 不能上线。会话按会话标识带回上下文，不写进客服工程。

**不可变版本与发布。** 草稿可改。一旦灰度或全量，整份规格冻结，版本号不再原地改。提示词、调用方式、会话、工具和知识任一变化，都要创建新版本并重新评测，评测结果绑定这一份规格。未过门禁时可以离线试跑或影子验证，不能保存任何正式流量。没有旧版本时，灰度没分到的流量继续原有业务流程，没有原流程就转人工。有上一稳定版才能回滚。第一次停止服务用下线：停掉新请求，并写明降级去向，状态不是已回滚。

**评测门禁。** 门槛由业务配置，平台负责拦住没通过的正式流量。A 的发布前检查是格式和安全；能不能放量，还要看线上有没有越过延迟预算。B 看红线召回和总体准确率，有一项没到就不能接入流量。C 看总体命中，以及关键政策错误是否超过 0。

**观测与回溯。** 每次调用记下版本、输入、工具、输出和耗时。B 的复核、A 的坏案例、C 的质检都靠它。回滚用来止损，日志用来解释原因。

**复用。** 模板、工具、知识库和评测集可以被下一支团队挂上。模板只预填配置，不复制三套运行时。

## 4. 模块与分期

分期原则：缺了这项，任一首批场景就无法安全上线，就放进一期。不是只看有没有多个团队一起用。

### 一期

1. 空间与角色。区分创建者和发布者。灰度和下线若谁都能点，B 不能进生产。
2. 三种场景模板。预填调用方式、会话开关和默认门槛，业务方不用从空白规格开始。
3. 规格编辑。提示词、调用方式、会话、工具、知识和服务说明都在发布前改完；发布后冻结，否则版本不可信。
4. 离线试跑和影子验证。未过门禁时仍要能看输出，但不能写入正式流量。
5. 不可变版本。已发布规格不能原地改；有上一稳定版才保留回滚，首次发布则提供下线。
6. 评测。发起评测、看通过条数和失败样例、改规格后重测。结果绑定整份规格，未通过不能放流量。
7. 灰度、全量、回滚和下线。没有旧版本时要说明其余流量去哪；有上一稳定版才能回滚。A 记录分组、归因、样本量和观察窗口。
8. 调用日志。B 的复核追溯必需，也支撑三类场景排障。
9. 基础观测。没有延迟预算、红线召回和关键政策错误，灰度无法决定放量还是停下。
10. 配额开关。把 A 的在线高峰和 B 的批量隔开。账单放到二期。
11. 批次标识、单条失败和重试入口。B 不自建调度也要能看见失败并重试，否则不能安全上线。

发布决策按写明的门槛执行。

- A 的延迟预算是 P95 ≤ 200ms。v1.9 为 210ms，线上 v1.8 为 180ms，已经触线。采纳率 31% 到 36%，点击率 4.2% 到 4.8%，次日留存 22.0% 到 23.1%。分组用用户哈希，曝光归因到版本，并记录样本量和 48 小时观察窗口。本原型不展示显著性结论；放量需结合分组样本、观察窗口和业务护栏。采纳率上升不能抵消超预算，正确动作是回滚到仍保留的 v1.8。若预算写成 300ms，210ms 就可以不因此回滚；门槛必须先写出来。
- B 的总体准确率 96.1%，门槛 98%。红线类别召回 91%，门槛 99%。误判率 2.4%，漏判率 8.9%，隐晦导流切片召回 86%。大量正常样本会抬高总体准确率，所以召回没达标同样不能灰度。流量留在 v3.2。模型与提示词可以回到 v3.2；如果对应政策已经废止，不能把旧政策一起恢复，该部分降级人工。
- C 的总体政策命中 93%，门槛 95%。关键政策错误 2 条，门槛 0。知识 v3 因此未通过，不能按 10% 灰度。一次解决率 71%、转人工率 18% 是线上 v2 的观察值。新政策生效后，回滚只能退模型或提示词，不能退回已失效政策；答不上来就转人工。

### 二期

1. 完整实验平台：显著性、多版本长期实验、自动停止。一期只记录分组、归因、样本量和观察窗口，不在原型里下显著性结论。
2. 自建批量调度：队列、断点续跑、文件导入导出。一期沿用既有调度，批次和单条失败已经可见。
3. 能力市场。等至少两个团队真实复用后再做，避免空货架。
4. 多 Agent 编排画布。三份需求都是单 Agent 加工具。
5. 自动改写提示词。策略责任在业务团队。
6. 成本分账。配额已经能隔离流量。
7. 人机工作台。审核台和客服台留在业务系统。平台给出降级信号和日志。

## 5. 行业对照

对照时间是 2026 年 10 月 12 日，依据是当时能打开的官方文档，不是实测对方全部控制台。

Dify 的云文档和自托管文档都写了 Chatflow、Workflow 的版本管理：当前草稿、最新发布版、历史版本；可以把历史版本恢复进草稿，再用 Publish Update 重新发布。云上 Sandbox 计划固定跑最新发布版；恢复历史版本、按指定版本调用 Service API 写在付费能力里。企业版文档 3.13.x 同样有版本恢复。来源：docs.dify.ai 的 Version Control。

LangSmith 的 Assistants 文档写明：图部署之后可以创建多个 Assistant；每次修改配置产生新版本，把任一版本设为当前版本即可回退。部署侧用 revision 发布新的代码版本，并用带版本号的镜像便于退回旧镜像。来源：docs.langchain.com 的 Assistants、Deployment revisions。不能说 LangSmith 不负责创建和发布。

扣子、阿里云百炼也提供应用搭建、知识和发布。版本和回滚不是别人没有的能力。

这个平台要补的是接上公司现有的模型服务、网关、离线任务和业务系统，并把三个团队的业务门禁放进同一次发布：未过门禁不能进正式流量，全量后仍能回到上一稳定版，政策失效时降级人工。这些规则外部平台不会按本公司场景预置。

## 6. 原型对应的闭环

原型使用假数据，不连接模型。评测页展示评测集、通过条数、失败样例和失败原因，并注明结果是模拟的。主路径是发布一个新 Agent：第一次评测失败；按失败样例补充引用要求后重测通过；才能保存 10% 正式流量。这 10% 之外的请求继续原有业务流程，没有原流程就转人工。保存之后规格冻结，版本仍是 v0.1；要再改，先创建新版本并重测。把流量调成 0 不会变成「已回滚」，停止服务要点下线。通过之前保存 10% 或 100% 都会被拒绝。调用方式或会话在通过后若被改掉，评测同样作废。

A 用来看全量之后的回滚。v1.9 已全量，v1.8 仍作为回滚目标留着。因为它的 P95 超过 200ms 预算，应回滚，不能再保存正式流量。B 用来看召回门禁：保存任何正式流量都会被拒绝，只能离线试跑或影子验证。C 用来看关键政策错误：知识 v3 不能灰度。
